**Why it matters** — the constructors no longer say what these classes need: two page ViewModels resolve dialog views from the container (and fall back to `new XView()` when it has none, so a missing registration goes unnoticed), `InstanceLauncher` hides the `IAppWindows` cycle that `BUG-FACC` was about instead of removing it, and `AppWindows` pulls seven fixed services out of the provider beside its legitimate window-factory use.

### EXC-01 — [High] An unreadable accounts file is read as "no accounts", silently, and then overwritten

**Locations**
- `src/Enigma.GitClient.Core/Hosting/HostAccountService.cs:346-351`

**Why it matters** — a truncated or hand-edited `host-accounts.json` makes every connected account disappear without a log line or a message; the next account added rewrites the file with that one account, and the others are gone for good while their tokens stay orphaned in the token store. `SettingsService`, `IdentityProfileStore`, `HiddenBranchStore` and `RepositoryListStore` all log and keep a `.corrupt` backup for exactly this case; this service has no logger at all.

**Recommended fix** — inject `ILogger<HostAccountService>`, and on `JsonException` log a warning with the exception and move the file to a timestamped backup before returning the empty list, the way `SettingsService.Read` does.

**Rule** — review-standards `reference/exceptions.md` §Catch blocks (catch swallowing, returning a default); `reference/logging.md` §Exceptions in logs.

### SEC-01 — [High] System programs are started by bare name, and `cmd.exe` is looked up in the repository

**Locations**
- `src/Enigma.GitClient.Desktop/Services/SystemInterop.cs:210`
- `src/Enigma.GitClient.Desktop/Services/SystemInterop.cs:207`
- `src/Enigma.GitClient.Desktop/Services/SystemInterop.cs:122`
- `src/Enigma.GitClient.Core/Git/GitExecutable.cs:81`

**Why it matters** — with `UseShellExecute = true`, `ProcessStartInfo.WorkingDirectory` is documented as the directory that *contains* the program to start, and it is set to the repository: where Windows Terminal is not installed, "Open terminal" on a cloned repository that ships a `cmd.exe` at its root runs that file. The bare `wt.exe`, `explorer.exe` and the `git` fallback go through `CreateProcess`, which searches the application's current directory before the system directories — the repository again when the client was started from a shell inside it. A repository is content another person authors. Assumption: the shell lookup was not exercised in this review; confirm it with a planted `cmd.exe` first, and treat the finding as Critical if it reproduces.

**Recommended fix** — never start a system program by bare name: build `cmd.exe` from `Environment.SystemDirectory`, `explorer.exe` from the Windows directory and `wt.exe` from `%LOCALAPPDATA%\Microsoft\WindowsApps`, skip a candidate whose file does not exist, and make the `git` fallback fail with `GitNotFoundException` instead of returning the bare name. Add a test that `TerminalCandidates` yields rooted paths only on Windows.

**Rule** — review-standards `reference/security.md` §Injection (command injection, `UseShellExecute = true` with input) and its severity note on content another person can author.

### SEC-02 — [High] The token store, its key and the accounts list are written in place, not atomically

**Locations**
- `src/Enigma.GitClient.Core/Security/TokenStore.cs:657`
- `src/Enigma.GitClient.Core/Security/TokenStore.cs:663-673`
- `src/Enigma.GitClient.Core/Security/TokenStore.cs:709`
- `src/Enigma.GitClient.Core/Security/TokenStore.cs:713-723`
- `src/Enigma.GitClient.Core/Hosting/HostAccountService.cs:360`
- `src/Enigma.GitClient.Core/Hosting/HostAccountService.cs:365-375`

**Why it matters** — a crash, a kill or a full disk in the middle of `File.WriteAllText` / `FileMode.Create` leaves a truncated file: a truncated key or token file makes every stored token unreadable (the reset is the only way out), and a truncated accounts file falls into EXC-01. The application runs as several instances by design, and a second instance reading during the write sees the same partial file. `AtomicFile` exists for this and the settings, profiles, repository list and hidden branches already use it; the three files that hold or index secrets do not.

**Recommended fix** — write all three through `AtomicFile` (temporary file in the same directory, then replace), extending it with an overload that takes the `UnixCreateMode` so the temporary file is created `0600` on Linux before the rename.

**Rule** — review-standards `reference/security.md` §Data at rest; `reference/exceptions.md` §Disposal and `finally` (a write that can be cut short).

### SOLID-04 — [Medium] The transient `DiffViewerViewModel` is captured by a singleton's constructor and can never unsubscribe

**Locations**

### SOLID-05 — [Medium] The git process runner carries three copies of the same run-wait-log-kill sequence

**Locations**
- `src/Enigma.GitClient.Core/Git/GitProcessRunner.cs:90-129`
- `src/Enigma.GitClient.Core/Git/GitProcessRunner.cs:195-223`
- `src/Enigma.GitClient.Core/Git/GitProcessRunner.cs:225-254`

**Why it matters** — every git invocation of the application goes through one of these three; they differ only in how standard output and standard error are read, so a fix to the shared part — the kill on cancellation, the standard-input hand-over, the completion log — has to be made three times and can be made twice.

### LOG-01 — [Medium] No durable log sink: 144 log calls reach only the host's default providers

**Locations**
- `src/Enigma.GitClient.Desktop/App.axaml.cs:137-148`

**Why it matters** — the host is built with the default providers and a minimum level and nothing else. The application is a `WinExe`: on Windows the console provider writes nowhere, the debug provider needs a debugger, and only warnings and errors reach the Event Log under the generic .NET source; on Linux everything goes to the standard output of a process usually started from a launcher. The safety net's "Something went wrong" dialog and every "see the log" style failure leave a user with no file to attach to a report, and the `Debug` lines of the git runner are unreachable in the field.
