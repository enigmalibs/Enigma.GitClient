# BUG-1840 — Long context menu items are clipped

**Status:** TODO
**Type:** BUG
**Branch:** `bugfix/bug-1840-context-menu-width`
**Run:** feature/2026-09-24-toolbar-refresh-theme-menus

## Objective

Some context menu items carry long titles — a history line's `Merge "feature/…" into "release/…"`,
`Reset "<branch>" to this commit - Hard (discard all changes)`, a host link naming the host — and the
menu cuts them off instead of showing them whole. Every context menu item's title must always be
fully visible.

## Context & constraints

- FluentTheme's `ContextMenu` theme sets `MaxWidth="{DynamicResource FlyoutThemeMaxWidth}"` (456 px).
  A `MenuItem` header is a `ContentPresenter` (`PART_HeaderPresenter`) in a star column with no
  trimming, so a header wider than what is left of those 456 px is clipped.
- The application's menus are all `ContextMenu`s (history lines, ref badges, file rows, branch/tag/
  remote rows); no `MenuFlyout` is used.
- A local style in `Themes/Styles.axaml` outranks the control theme's setter.

## Decisions taken autonomously

| Question | Chosen | Why | Alternatives rejected |
|---|---|---|---|
| The fix | Lift the width cap on every `ContextMenu` (`MaxWidth` → infinity), so a menu is as wide as its widest item | Fixes every menu at once, including the data-built history menu | Shortening the titles (they carry the branch names the reader needs); a bigger fixed cap (still clips a long enough branch name) |
| A title wider than the screen | The header wraps (`TextWrapping="Wrap"` on `PART_HeaderPresenter`) instead of running off the edge | "Always fully visible": the popup is bounded by the screen, and wrapped text is still all there | Trimming with an ellipsis (hides part of the title) |
| Where | `Themes/Styles.axaml`, application-wide | One rule for every menu in the application | Per-menu `MaxWidth` (every new menu would need it) |

## Steps

1. `Themes/Styles.axaml`: `ContextMenu` → `MaxWidth` infinity; `MenuItem /template/
   ContentPresenter#PART_HeaderPresenter` → `TextWrapping="Wrap"`; a comment says why.
2. Tests (`App.UnitTests`, headless): a context menu with an item whose title is far wider than
   456 px opens with the item's header presenter at least as wide as the title's desired width (no
   clipping); the menu's `MaxWidth` is not the Fluent cap.

## Acceptance criteria

- A context menu item with a long title shows the whole title.
- Build clean with zero warnings; the whole suite green.

## Out of scope

- Menus opened by other platforms' native menu bars.
