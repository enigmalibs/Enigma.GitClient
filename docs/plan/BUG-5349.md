# BUG-5349 — Long dialog questions are cut off

**Status:** TODO
**Type:** BUG
**Branch:** `bugfix/bug-5349-wrapping-dialog-questions`
**Run:** bugfix/2026-09-28-history-tag-push-release

## Objective

*Discard uncommitted files…* on the history's uncommitted line asks "Throw away every uncommitted
change — *N files*, staged or not, untracked files included? This cannot be undone." The dialog cuts
the question off at its edge. A question must go onto as many lines as it needs, and never be cut.

## Context & constraints

- **The question is a plain string.** `ContentDialogServiceExtensions.ConfirmDestructiveAsync` sets
  `dialog.Content = message`. The Enigma `ContentDialog` (Enigma.Avalonia.Desktop 1.1.0) shows a
  string through its template's `ContentPresenter`, which draws it as one line that does not wrap.
- **The card is bounded.** The window's `HostDialog` is `DialogMaxWidth="720"`, and the start window's
  host keeps the library's default (600). A line longer than that is clipped.
- **It is not only this question.** Other questions pass a plain string too, and are cut the same way
  once they are long enough:
  - `StashOperations` — deleting a stash;
  - `TagOperations` — deleting a tag;
  - `BranchOperations.ConfirmAsync`;
  - `ConflictResolutionPageViewModel.ConfirmAsync`;
  - `AppWindows`.
- **The shared styles** live in `Themes/Styles.axaml`, which already styles the dialog's template
  parts (`contentDialog|ContentDialog.danger /template/ Button#PART_PrimaryButton`).
- `DestructiveConfirmationTests` shows the real dialog in a headless window, so the layout can be
  measured.

## Steps

1. Confirm the cause with a headless test: show the real dialog, in a 720-wide host, with the discard
   question for 12 files, and look at the text it lays out.
2. `Themes/Styles.axaml`: one style that makes the dialog's content presenter wrap the text it is
   given (`TextWrapping="Wrap"`), with a comment saying why. That covers every plain-string question
   at once. `Wrap` rather than `WrapWithOverflow`, so that a long word with no break in it (a path, a
   URL) is broken too rather than cut.

   If the presenter does not pass the wrapping on to the text it builds, fall back to a wrapping
   `TextBlock`, built by one shared helper that every plain-string question goes through. Record the
   fallback in the completion doc.
3. Tests:
   - the discard question in a 720-wide host lays out on more than one line, no wider than the card,
     and is not trimmed;
   - a question passed through the plain `ShowAsync` wraps too (the tag delete, with a long name);
   - a short question still fits on one line;
   - the existing `ConfirmDestructiveAsync` tests stay green.

## Acceptance criteria

- The discard question shows in full, on as many lines as it needs, in the window's dialog and in
  the start window's.
- No plain-string question in a dialog is cut: all of them wrap.
- Build clean with zero warnings; the whole suite green.

## Out of scope

- Rewording any question.
- Changing the dialogs' widths.
- Questions whose content is a view of its own (create a tag, the stash dialog, …): they lay out
  their own text.

## Decisions taken autonomously

| Question | Chosen | Why | Alternatives rejected |
|---|---|---|---|
| Fix the one question, or all of them | Every plain-string question, from one theme style | The cause is shared: every such question is cut once it is long enough. One style fixes them all, and new questions are covered too | A wrapping `TextBlock` in `ConfirmDestructiveAsync` only (the tag, stash and branch questions would stay cut) |
