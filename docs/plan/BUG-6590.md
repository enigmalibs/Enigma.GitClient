# BUG-6590 — A refresh resets the working-tree diff

**Status:** DONE — see `docs/done/BUG-6590.md`
**Type:** BUG
**Branch:** `bugfix/bug-6590-diff-refresh-keeps-place`
**Run:** vibe/2026-10-06-diff-search-refs-release

## Objective

While the diff of an uncommitted file is open, the automatic refresh (every 15 s by default) no
longer:

- scrolls the reader back to the first change;
- clears their text selection;
- throws away the context they expanded, or a "Show anyway".

The diff is redrawn only when what it shows changed: the file's patch is different, the file left the
half it was picked in (staged or unstaged elsewhere), or the file is gone from the working tree.

## Context & constraints

- **The path a refresh takes today:**
  1. `RepositoryContext.StateRefreshed` → `WorkingTreePanelViewModel.OnStateRefreshed` →
     `RefreshAsync` → `Apply(status)`;
  2. `Apply` re-lists both halves, re-selects the same path, then `UpdateSelectedChange` raises
     `SelectionChanged` — every time, by design ("or is picked again by a refresh that re-read it");
  3. `HistoryPageViewModel.OnWorkingTreeSelectionChanged` → `Diff.ShowAsync(repository, target, file)`;
  4. `DiffViewerViewModel.ShowAsync` resets `ContextLines` to 3 and the size limit, then `ReloadAsync`
     → `Apply(patch)`, which clears `Render.Selection`, replaces the rows and raises `PatchChanged`;
  5. `DiffViewerView` answers `PatchChanged` by scrolling to the first change.
- **Commit diffs are not affected:** the history defers its own in-place redraw while the diff view
  is open (`_refreshPending`).
- **File watchers were considered and rejected** (see *Decisions*): the bug is the unconditional
  redraw, not the polling.
- `DiffTarget.WorkingTree()` / `DiffTarget.Staged()` build a new instance per call: comparing targets
  needs value equality (check `DiffTarget`).
- Test doubles: `RecordingDiffService`, `TestServices`, the headless fixture.

## Steps

1. `DiffViewerViewModel`:
   - a way to say "this is the file already shown" — same repository, same target (by value), same
     path — e.g. `IsShowing(RepositoryHandle, DiffTarget, string path)`;
   - `RefreshAsync(ChangedFile file)`: takes the (possibly newer) `ChangedFile`, re-reads the patch
     with the options as they stand (context, whitespace, size limit kept), and **applies it only
     when it differs** from the patch on screen (patch text, binary/submodule/truncation flags, change
     kind, paths — and the message when there is no patch). An identical read changes nothing: no
     row replacement, no selection clear, no `PatchChanged`, no busy flicker;
   - a refresh read that fails keeps what is on screen and logs; a stale read (the reader picked
     another file meanwhile) is dropped by the existing generation counter.
2. `HistoryPageViewModel.OnWorkingTreeSelectionChanged`: when the viewer already shows the picked
   change, call `Diff.RefreshAsync(change.File)`; otherwise `Diff.ShowAsync` as today.
3. Tests (headless, `RecordingDiffService` or a real repository):
   - a refresh that reads the same patch leaves the rows instance, the selection, the context lines
     and the size limit untouched, and raises no `PatchChanged`;
   - a refresh after the file's content changed redraws (new rows, `PatchChanged` once);
   - a file staged elsewhere (moves halves) is shown fresh;
   - a file that leaves the working tree clears the diff (existing behaviour, pinned);
   - picking another file and coming back still starts from the default context.

## Acceptance criteria

- With the diff of an unstaged or staged file open, an automatic refresh that finds the file
  unchanged keeps the scroll position, the text selection and the expanded context.
- A refresh that finds the file changed redraws it, as a newly opened file is drawn.
- A refresh that finds the file gone from its half (staged, unstaged, committed, discarded) behaves as
  today.
- Release build clean with zero warnings; the whole suite green.

## Out of scope

- File-system watchers for the working tree.
- Keeping the scroll position across a patch that did change.
- Commit diffs (unaffected).

## Decisions taken autonomously

| Question | Chosen | Why | Alternatives rejected |
|---|---|---|---|
| Fix approach | Re-read on refresh, redraw only when the patch changed | The bug is the unconditional redraw; the re-read already happens and costs nothing new | `FileSystemWatcher` (a cross-platform subsystem: inotify watch limits, buffer overflows on large trees, `.git`/ignored-file noise and debouncing, while the polling stays needed for index/HEAD/remotes); pausing the refresh while a diff is open (stale content) |
| A file that did change | Redrawn as a newly opened file (first change, selection cleared) | The draft accepts it; an old offset points at different lines in a new patch | Keeping the offset across a changed patch |
| Context expanded / "Show anyway" across a refresh | Kept | They are the reader's place, like the scroll | Reset at every refresh (today's behaviour) |
| A refresh read that fails | Keep the diff on screen, log | A transient git error must not replace a good diff with an error | Showing "The diff could not be read." |
| Where "same file" is decided | The history asks the viewer (`IsShowing`) | The viewer is what knows what it shows; the panel's `SelectionChanged` contract stays as documented | A new event argument on the panel |
