# FEATURE-EAB7 — Windows MSI build script

**Status:** TODO

**Branch:** one per phase, see below

## Objective

One command builds the Windows installer: `packaging/windows/buildmsi.ps1` (and a `buildmsi.bat` twin)
cleans the repository, publishes the release, and builds `artifacts/Enigma.GitClient.X.Y.Z.msi` with
Enigma.Msi. The repository carries a copy of Enigma.Msi's worker CLI.

## Context & constraints

- **The installed product.** This machine has *Enigma Git Client 6.13.0* installed from an MSI built
  with Enigma.Msi (read from its cached package, read-only, while planning):
  - `UpgradeCode` `{871622D1-A9C6-4C72-B6A3-E8D8104AD5C3}`;
  - `ProductName` "Enigma Git Client", `Manufacturer` "Josué Clément", `ALLUSERS` 1 (per machine);
  - `INSTALLDIR` = `ProgramFilesFolder\Enigma Git Client`;
  - shortcuts "Enigma Git Client" in `DesktopFolder` and `ProgramMenuFolder`, target
    `[INSTALLDIR]\Enigma.GitClient.Desktop.exe`, icon `app.ico`; `ARPPRODUCTICON` set.
  The new script must keep that upgrade code. A new one would install 6.14.0 beside 6.13.0 instead of
  upgrading it.
- **Enigma.Msi** (`C:\Dev\EnigmaLibs\Enigma.Msi`, tag `1.7.0` = `a7a1bfb`, clean tree):
  - Its worker, `Enigma.Msi.Worker.exe build <file.msipkg.json>`, is a net472 CLI. Exit codes: `0` built,
    `1` invalid package or failed build, `2` bad invocation.
  - The CLI takes the profile as its whole input. Relative paths resolve against the working directory.
  - Its built output `src/Enigma.Msi.Worker/bin/Release/net472/` is self-contained. That build carries
    `1.0.0+a7a1bfb` (the library's own version), so it is the 1.7.0 tag.
  - WixSharp writes a `.wixsharp/` folder beside the worker on its first build.
  - Needs the WiX CLI (`dotnet tool install --global wix`); 7.0.0 is installed here.
- **Profile model** (`docs/guides/model.md` there): `appName`, `version`, `productId`, `upgradeCode`,
  `manufacturer`, `scope`, `install.installPath` / `releasePath`, `output.outputPath` / `msiFilename`
  (no `.msi`), `compression` (`None` … `High`), `controlPanel.productIcon`, `shortcuts[]`
  (`shortcutPath`, `shortcutName`, `targetPath`, `iconPath`).
- **Publish** (FEATURE-0D4E): `packaging/windows/publish.ps1` runs `dotnet publish
  src\Enigma.GitClient.Desktop -c Release -r win-x64 -p:PublishReadyToRun=true` and exits with dotnet's
  code. Result: `src\Enigma.GitClient.Desktop\bin\Release\net10.0\win-x64\publish\`, with `app.ico`
  beside `Enigma.GitClient.Desktop.exe` (FEATURE-5096).
- **The version** lives in `Directory.Build.props` (`<Version>`).
- `.gitignore` already ignores `artifacts/`, `*.pdb`, `[Bb]in/`, `x64/`, `[Rr]elease/`. The vendored
  folder must not match any of them, because `git clean -dxf` deletes ignored files.
- `.gitattributes` marks `*.dll` / `*.exe` binary; `*.bat` is CRLF.
- Windows PowerShell 5.1 reads a BOM-less script as ANSI, and `.editorconfig` says UTF-8 without BOM. So
  the `.ps1` stays ASCII.
- **Tests:** `DisplayNameConsistencyTests` (Core) and `AssemblyNameConsistencyTests` (Desktop) tie the
  packaging files to the product's name and the assembly. Core suites run here; Desktop tests are compiled
  only (the user's standing rule for this Windows machine).
- **The run may not run `git clean`** in this repository. The script is verified end to end in a scratch
  clone instead.

## PHASE02 — The buildmsi script

**Branch:** `feature/feature-eab7-phase02-buildmsi-script`
**Status:** TODO

### Steps

1. `packaging/windows/buildmsi.ps1` (ASCII, `Set-StrictMode`, `$ErrorActionPreference = 'Stop'`,
   comment-based help like `publish.ps1`), resolved from its own location:
   1. constants: upgrade code, product name, manufacturer, the executable's name;
   2. check `git`, `dotnet` and `wix` are on the `PATH`, and the vendored worker exists;
   3. read and check (`^\d+\.\d+\.\d+$`) the version in `Directory.Build.props`;
   4. `git -C <root> clean -dxf`; stop on a non-zero exit code;
   5. run `publish.ps1`; stop on a non-zero exit code; check that the exe and `app.ico` are in the
      publish folder;
   6. write `artifacts/Enigma.GitClient.X.Y.Z.msipkg.json` (UTF-8 without BOM, absolute paths, a new
      `productId`): `PerMachine`, `%ProgramFiles%\Enigma Git Client`, `compression` `None`,
      `controlPanel.productIcon` and both shortcuts' icon = the publish folder's `app.ico`, shortcuts
      `%Desktop%` and `%ProgramMenu%` named "Enigma Git Client" targeting
      `[INSTALLDIR]\Enigma.GitClient.Desktop.exe`;
   7. run `Enigma.Msi.Worker.exe build <profile>`; exit with its code; on success print the MSI's path.
2. `packaging/windows/buildmsi.bat`: runs `buildmsi.ps1` through `powershell -NoProfile
   -ExecutionPolicy Bypass -File`, and passes its exit code on.
3. Tests:
   - `DisplayNameConsistencyTests`: `buildmsi.ps1` names the product `ProductInformation.DisplayName`;
   - a new Core test pins the upgrade code;
   - `AssemblyNameConsistencyTests`: `buildmsi.ps1`'s shortcuts target `<AssemblyName>.exe`.
4. Docs:
   - `README.md` *Publish*: the Windows installer;
   - `docs/RELEASE.md`: §5/§6 (Windows has an installer now), and *Why there is no MSI profile* becomes
     *The Windows installer* (the upgrade code is fixed in the script).
5. Verify in a scratch clone: commit the dev's tree there, run `buildmsi.bat`, then read the MSI's
   `Property`, `Directory`, `Shortcut`, `Upgrade`, `Icon` and `Media` tables.

### Acceptance criteria

- In the scratch clone, `buildmsi.bat` exits 0 and leaves `artifacts/Enigma.GitClient.<version>.msi`
  and its `.msipkg.json`. After it, `git status --porcelain` is empty.
- The MSI's tables show:
  - `ProductName` "Enigma Git Client", `Manufacturer` "Josué Clément", `ProductVersion` = the
    `Directory.Build.props` version;
  - `UpgradeCode` `{871622D1-A9C6-4C72-B6A3-E8D8104AD5C3}`, `ALLUSERS` 1, `ARPPRODUCTICON` set;
  - `INSTALLDIR` "Enigma Git Client" under `ProgramFilesFolder`;
  - two "Enigma Git Client" shortcuts (`DesktopFolder`, `ProgramMenuFolder`) on
    `[INSTALLDIR]\Enigma.GitClient.Desktop.exe`, each with an icon.
- The profile says `"compression": "None"`.
- A missing `wix` stops the script before `git clean`, with the install command in the message.
- The Release build has zero warnings; the Core suites (with the new tests) show no new failure.
