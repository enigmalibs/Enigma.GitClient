# BUG-6787 — Diff text cannot be selected

**Status:** IN PROGRESS
**Type:** BUG
**Branch:** one per phase, see below
**Run:** feature/2026-09-30-profile-lists-readme-diffs

## Objective

In the diff viewer, for committed and uncommitted files and in both panes of the side-by-side view
(and in the unified view, which draws the same lines), the reader cannot select text. Make the text
selectable and copyable. It stays read-only.

## Context & constraints

- `Views/Panels/DiffViewerView.axaml`: two `ListBox`es (`UnifiedList`, `SideBySideList`) of
  `DiffRowViewModel` rows, `SelectionMode="Multiple"`, virtualised. Each line's text is a
  `Controls/Diff/DiffLineText`: a `Control` that draws one `FormattedText`. It expands tabs to a
  column grid (`Expand` keeps a map from drawn characters back to the raw text), tints the word-level
  segments, scrolls by `HorizontalOffset` (in characters, applied at render), and clips itself. It
  has no hit testing and no selection.
- The same viewer serves every diff: `HistoryPageView` hosts it once, for commit files and working
  tree files alike. `DiffLineText` is also used by the conflict page, which must stay as it is.
- `DiffViewerViewModel`: `Render` (`DiffRenderOptions`, shared by every row: whitespace, wrap, tab
  width, the two horizontal scroll states), `UnifiedRows` / `SideBySideRows` built in order from
  `DiffRowBuilder`, `Selection` (the list's selected rows), and `CopySelectionCommand` (copies the
  selected rows' lines). That command is not bound anywhere.
- A row is a hunk band (no text), or cells: `Single` (unified), `Left` / `Right` (side by side). A
  cell with no `Line` is a filler.
- `DiffViewerView.axaml.cs` already routes the tunnelled wheel. The house pattern for an in-app
  pointer gesture is in `BranchesPageView.axaml.cs` (`BranchDragGesture.IsDrag`, `ScrollFor`, capture,
  timer). Colours come from `Themes/Graph.axaml` (`Diff*Color` / `Diff*Brush`, dark and light), and
  styles from `Themes/Styles.axaml`.
- Tests: `DiffViewerTests` (headless, with `RecordingDiffService` and `RecordingSystemInterop` for the
  clipboard) and `DiffTypographyTests`.

## PHASE01 — The text selection and its drawing

**Branch:** `bugfix/bug-6787-phase01-selection-model`
**Status:** DONE — see `docs/done/BUG-6787-PHASE01.md`

### Steps

1. `Controls/Diff/DiffTextSelection.cs`:
   - `DiffPane` (`Unified`, `Left`, `Right`) and `DiffTextPosition(Row, Column)`, comparable;
   - `DiffTextSelection`: `Pane`, `Anchor`, `Caret`, `Start` / `End` (ordered), `IsEmpty`,
     `Begin(pane, position)`, `ExtendTo(position)`, `Clear()`, and a `Changed` event;
   - `RangeOn(row, pane, length)`: the raw character range selected on that row, or none;
   - `Text(lineAt)`: the selected text, one line per row, skipping rows with no line in the pane
     (bands, fillers, the missing-newline marker).
2. `DiffRenderOptions.Selection`, one instance shared by every row. `DiffRowViewModel.Index` is set as
   the rows are built. `DiffRowViewModel.CellFor(pane)`.
3. `DiffLineText`:
   - `Selection`, `Row`, `Pane` and `SelectionBrush` properties;
   - it repaints when the selection changes, and draws its selected range behind the glyphs (raw
     range mapped through the tab expansion, at the scrolled origin);
   - `IndexAt(point)`: the raw character index under a point, allowing for the scroll, the tabs and
     the wrapping; past the end gives the length.
   Without a `Selection` it behaves exactly as today (the conflict page).
4. `DiffViewerView.axaml` binds `Selection`, `Row` and `Pane` on the three `DiffLineText`s. Add a
   `DiffTextSelectionBrush` for both themes and set it through a style.
5. `DiffViewerViewModel` clears the selection when a new patch, a re-read or another rendering
   arrives, and `SelectedText()` gives the text of the current selection.
6. Tests:
   - the selection arithmetic: forward and backward, one row, several rows, another pane, empty;
   - the text: partial first and last lines, bands and fillers skipped, the side-by-side panes kept
     apart;
   - `DiffLineText.IndexAt` with tabs and a scroll offset;
   - the viewer clears the selection on a new file, and numbers its rows.

### Acceptance criteria

- A selection set on the viewer is drawn on exactly the characters it covers, in the right pane.
- The selected text is what the reader sees, line by line, without numbers or markers.
- Nothing changes for the conflict page.
- Build clean with zero warnings; the whole suite green.

## PHASE02 — Selecting and copying with the pointer

**Branch:** `bugfix/bug-6787-phase02-pointer-selection`
**Status:** TODO

### Steps

1. `DiffViewerView.axaml.cs` (tunnelled pointer handlers, as the page's wheel is):
   - a left press on a line's text starts a selection in that pane (Shift extends it), and the
     press still selects the row as before;
   - moving with the button held, past the drag threshold, captures the pointer on the list and
     extends the selection to the character under the pointer. The row is hit-tested, and the
     pointer's column is clamped to that row's text in the same pane;
   - the list scrolls while the pointer is held near its top or bottom (`BranchDragGesture.ScrollFor`
     and a timer), extending the selection as it goes;
   - release or a lost capture ends the gesture. A click without a move leaves an empty selection,
     which clears the highlight.
2. Copying:
   - Ctrl+C copies the selected text, or, when there is none, the selected rows
     (`CopySelectionCommand`);
   - a context menu on both lists with "Copy", enabled when there is something to copy.
3. Read-only: no caret, no editing, nothing else accepts keyboard input.
4. Tests (headless pointer, `RecordingSystemInterop`):
   - a drag from one line to another selects across them in that pane only, and Ctrl+C copies it;
   - Shift+click extends; a plain click clears;
   - side by side, the left and right panes select separately;
   - the "Copy" menu item copies;
   - a new file clears the selection.

### Acceptance criteria

- In both renderings, and for committed and uncommitted files, the reader can drag across the diff's
  text to select it, and copy it with Ctrl+C or the menu.
- The text cannot be edited.
- Build clean with zero warnings; the whole suite green.

## Out of scope

- Selecting from the keyboard (Shift+arrows), Ctrl+A, double-click word selection.
- Selecting across both panes of the side-by-side view at once.
- Text selection on the conflict resolution page.
