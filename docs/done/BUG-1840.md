# BUG-1840 — Long context menu items are clipped

**Item:** BUG-1840 — Long context menu items are clipped
**Branch:** `bugfix/bug-1840-context-menu-width`
**Run:** feature/2026-09-24-toolbar-refresh-theme-menus

## Summary

Every context menu in the application — a history line's, a branch badge's, a changed file's, the
branch, tag and remote rows' — now draws each item's title whole. FluentTheme capped a `ContextMenu`
at its flyout width (456 px) and a `MenuItem` header has no trimming, so a title longer than what was
left — `Merge "feature/…" into "release/…"`, a hard reset naming a long branch — was cut off at the
right edge. The cap is lifted, so a menu is as wide as its widest item, and a title wider than even
the screen breaks onto a second line instead of running off the menu.

Reproduced first: the test measured a 653 px title given 408 px, in a menu capped at 456 px.

## Files / modules touched

**Modified — App**

- `Themes/Styles.axaml` — `ContextMenu` → `MaxWidth` infinity; `MenuItem /template/
  ContentPresenter#PART_HeaderPresenter` → `TextWrapping="Wrap"`; a comment saying why

**Tests**

- `App.UnitTests/ContextMenuWidthTests.cs` (new) — an opened menu gives a 653 px title all of its
  width on one line; a menu is no longer capped at the flyout width; the header presenter wraps as the
  last resort

## Decisions taken at build time

| Question | Chosen | Why |
|---|---|---|
| How "fully visible" is asserted | The header presenter and its text block are at least as wide as the title measured unconstrained in the same face and size | Checks what the reader sees rather than a style value; the style values have their own tests |
| Where the wrap is set | `ContentPresenter.TextWrapping` on the template part | It reaches the text block the presenter builds for a string header, whether the item is declared in markup or built from data (the history's `ItemContainerTheme`) |
