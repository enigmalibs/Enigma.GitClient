# BUG-5349 — Long dialog questions are cut off

**Item:** BUG-5349 — Long dialog questions are cut off
**Branch:** `bugfix/bug-5349-wrapping-dialog-questions`
**Run:** bugfix/2026-09-28-history-tag-push-release

## Summary

A question asked as plain text now goes onto as many lines as it needs, and is never cut at the
dialog's edge.

- **The cause, confirmed first by a failing headless test.** The Enigma `ContentDialog` draws a string
  as a one-line text block, which does not wrap. The card is bounded (720 wide in the repository
  window, the library's 600 in the start window), so the discard question for the uncommitted work
  was clipped.
- **The fix.** One style in `Themes/Styles.axaml` gives every `ContentDialog` a content template for
  strings: a `TextBlock` with `TextWrapping="Wrap"`.
  - Every plain-string question is covered in both windows: discarding the uncommitted work, deleting
    a stash, a tag or a branch, the conflict page's questions, and "git is required".
  - `Wrap` rather than `WrapWithOverflow`, so a word with no break in it (a long tag name, a path) is
    broken too rather than cut.
- **What it does not touch.** A dialog whose content is a view of its own (a form, the tool pages) is
  used as it is and never goes through the template, so its text keeps its own layout.

## Files / modules touched

## Decisions taken at build time

| Question | Chosen | Why |
|---|---|---|
| A style on the presenter's `TextWrapping`, or a content template | A content template for `x:String` on the dialog | The presenter's `TextWrapping` is inherited: set in the dialog's template, it made every text block of every dialog view wrap. The new view test caught it; nothing else in the suite did. A `ContentTemplate` is only used for content that is not a control. |
| Where the template is set | On `ContentDialog` itself, by a style | Its public `ContentTemplate`, which its presenter follows; `ShowAsync`'s reset leaves it alone (the tests show the real dialog through the real service). No call site changes. |
| How the test measures "not cut" | The text's width without trailing spaces (`TextLayout.Width`) against the block, and the block against `DialogMaxWidth` | A wrapped line keeps its trailing space and does not draw it; counting it overstated the width by a space's width |

## Deviations & follow-ups

- The plan's first choice, `TextWrapping` on the dialog's content presenter, was replaced by a content
  template, for the reason above. The plan's fallback, a helper at every call site, was not needed:
  the template fixes every call site at once.
- Line endings: no CRLF churn.

## Documentation sweep

Nothing in the README or the other docs describes how a dialog lays out its text. No edit. The fix
